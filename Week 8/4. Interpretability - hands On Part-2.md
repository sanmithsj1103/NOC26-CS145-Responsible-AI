# Interpretability Hands-on - Part 2

### Introduction
Understanding how complex neural networks make predictions is a critical challenge in artificial intelligence. This tutorial delves into the interpretability of codebook models, specifically those trained on the algorithmic sequence modeling dataset known as TOC-FSM (Finite State Machine). By examining these models, we aim to shed light on their internal mechanisms, such as how they represent sequential data and how these representations influence their output.

The core idea is to use "codebook features" to analyze the learned representations within a GPT-NEO-X model. This involves not just observing the model's behavior but actively probing its internal states, intervening on its codes, and measuring the impact on predictions. For students and researchers, this hands-on approach provides valuable insights into the "black box" problem, demonstrating practical methods to evaluate and understand the decision-making processes of advanced neural architectures in sequence prediction tasks.

### Core Concepts
| Term | Definition | Significance |
| :--- | :--- | :--- |
| **`Codebook Models`** | Neural networks augmented with a discrete set of learned "codes" that represent features or patterns in the input data. | They provide a structured, interpretable layer for understanding how models categorize and process information. |
| **`TOC-FSM Dataset`** | A synthetic dataset generated from a Finite State Machine (FSM) with 100 states and 10 outbound edges per state. | Serves as a controlled environment to evaluate sequence prediction capabilities and interpret model learning. |
| **`Finite State Machine (FSM)`** | A mathematical model of computation that defines states and transitions between them based on inputs. | Provides the underlying structure for the TOC-FSM dataset, allowing for systematic generation of sequential data. |
| **`Code Purity`** | A measure of how exclusively a learned code is associated with a single input or a specific type of input pattern. | High purity indicates clear, unambiguous representations, aiding interpretability and reducing superposition. |
| **`Superposition`** | The phenomenon where multiple distinct inputs are mapped to the same hidden representation within a neural network. | It complicates interpretability by making it difficult to discern which input caused a particular activation or output. |
| **`JS Divergence (JSD)`** | Jensen-Shannon Divergence, a method to measure the similarity between two probability distributions. | Used to quantify how much two output distributions differ, indicating the impact of interventions or input changes. |
| **`Hooked Model`** | A modified version of a neural network that allows for easy access and intervention on its internal activations and states. | Essential for interpretability studies, enabling researchers to "hook into" and manipulate specific layers or codes. |
| **`Bigram/Trigram`** | Sequences of two (bigram) or three (trigram) consecutive tokens or states in a sequence. | Fundamental units of analysis in sequence modeling, used to evaluate code purity and input grouping. |

### Detailed Analysis

#### 1. Setting up the Environment and Model for FSM Sequence Prediction
The initial phase involves preparing the environment and the model for the TOC-FSM sequence prediction task. This includes importing necessary libraries from the `codebook features` framework and configuring the model for inference, as no training is performed in this interpretability tutorial.

The core model used is a GPT-NEO-X architecture, for which specific hyperparameters are defined:
- **States**: 100
- **Edges**: 10 (outbound neighbors per state)
- **Sequence Length**: 128
- **Run Name**: "Hooked Model NEOX"

The GPT-NeoX model is then wrapped with the pre-trained codebook model, creating a `CV model`. This `CV model` is set to evaluation mode (`eval()`) to prevent further training. A "hooked model" is subsequently derived from this `CV model`, allowing for internal state manipulation without altering the original model's parameters.

The TOC-FSM dataset is generated using a finite state machine. Sequences of transitions between states are created, where each state is represented by a two-digit tokenization (e.g., state 18 becomes "1, 8"; state 53 becomes "5, 3"). This tokenization scheme is crucial for how the model processes the input. The `fsm.npy` file stores the FSM model, and a `TokFSM dataset` class handles the tokenization and sequence generation.

An initial assessment of the model's predictive capability is performed by calculating the accuracy of the first transition prediction. For instance, the model achieved an accuracy of 97.5% in predicting the next state, indicating a decent baseline performance.

#### 2. Analyzing Code Purity and Superposition
Code purity is a key metric for understanding the clarity of learned representations. A "pure" code is one that is uniquely associated with a single input or a specific input pattern. The lecture illustrates this with an example: if code 2 is linked only to input '2', it's pure; if code 0 is linked to '0,0' and '0,1', it's not pure. The purity of a layer is the proportion of pure codes within it.

The process for calculating code purity involves:
- **Partitioning Input Space**: For each layer, the input space is partitioned for both bigrams (two-state sequences) and trigrams (three-state sequences). This creates dictionaries where keys are codes and values are sets of associated bigram/trigram inputs.
- **Counting Pure Codes**: The number of codes associated with only a single bigram or trigram input is counted.
- **Calculating Purity**: This count is divided by the total number of codes in the layer to get the purity score for bigrams and trigrams, respectively.

Observations from this analysis reveal:
- **Layer 1 MLP Purity**: The first MLP layer exhibits very high purity for both bigram and trigram inputs. This is significant because the model has 128 hidden states, but there are 1000 possible trigram combinations (100 states * 10 edges). Despite the hidden states being fewer than possible combinations, the high purity suggests that codebook training effectively resolves the "superposition problem" at this initial layer. Superposition occurs when multiple inputs map to the same hidden representation, making differentiation difficult.
- **Higher Layer Purity Decline**: As the model progresses to higher layers, code purity tends to decline. This is attributed to the model forming more complex predictions for the next token, requiring codes to represent more abstract and composite features beyond simple state transitions.

#### 3. Intervening on State Codes and Measuring Influence
This section explores how much the learned codes influence the model's output probability distributions. The methodology involves generating valid bigram inputs (e.g., 0-1, 0-2) and prepending them with random state prefixes (e.g., 5-4-3 for 0-1, resulting in 5-4-3-0-1).

The steps for intervention and measurement are:
- **Generating Valid Inputs with Prefixes**: All valid bigram inputs are identified, and random state prefixes of a specified length (e.g., 0 in this case, but can be up to 62 for paper reproducibility) are added. The `reverse FSM` is used to generate valid state sequences backward for prefix generation.
- **Tokenization and Tensor Conversion**: The generated sequences (e.g., "BOS 1 0 1" for a prefix "1" and input "0 1") are tokenized, padded, and converted into PyTorch tensors suitable for model input.
- **Calculating JS Divergence**: The Jensen-Shannon Divergence (JSD) is used to measure the difference between output probability distributions. Initially, JSD is calculated between the output distributions of all pairs of valid inputs (e.g., comparing the output for "5-4-3-0-1" with "8-7-6-0-2").
- **Patching Configurations**: The core of the intervention involves defining various "patching" configurations to observe their impact:
- `None`: No patching.
- `L0 attention`: Patching at Layer 0's attention mechanism.
- `L1 MLP`: Patching at Layer 1's MLP.
- `All attention`: Patching all attention layers.
- `All MLP`: Patching all MLP layers.
- `All attention and MLP`: Patching all attention and MLP layers.
- **Measuring Impact**: For each patching configuration, the model's raw logits and activations are obtained. Modified logits are then compared against the original logits using JSD. This measures how much modifying specific internal codes (via patching) affects the model's output distribution for a given input. A JSD adjustment (dividing by `number of states - 1`) is applied to exclude self-comparison JSD, which is always zero.
- **Visualization**: The results are visualized using bar charts, showing how different parts of the model (attention, MLP) and their learned codes influence the output distribution. A large effect on the output distribution of another input due to modifying codes for one input suggests a significant role of those codes in the model's decision-making.

#### 4. Grouping Inputs by Codes and Divergence Analysis
This final part investigates whether states grouped together by codes in the latent layers of the codebook model exhibit more similar output distributions compared to randomly selected states. The hypothesis is that states sharing a code should predict similar next tokens, leading to smaller JSD values.

The methodology involves:
- **Generating All Valid Trigram Inputs**: Using `itertools.product` and `FsmUtils.ValidInput`, all valid three-state sequences are generated.
- **Computing Logits and Cache**: The `Hooked model` processes each valid trigram input to obtain its logits and cache, which are stored in an `Allstate info` dictionary.
- **Calculating JSD for All Pairs**: `JS divergence 2` calculates the JSD between the logits of all possible pairs of trigram inputs, storing these divergence metrics.
- **Iterating Through Layers and Components**: For each layer and a specified component (e.g., MLP), the inputs are grouped by their associated codes.
- **Comparing Divergence**: The JSD between trigram input pairs grouped by the same code is compared against the JSD of randomly selected trigram input pairs.

The observations from this analysis support the initial hypothesis:
- **Layer 1**: Trigram input code pairs show relatively small JSD.
- **Higher Layers (Layer 2, Layer 3)**: While random trigram input pairs show increasing JSD as layers increase, trigram inputs grouped by codes continue to exhibit significantly smaller JSD. This indicates that the model effectively groups states that lead to similar predictions, even in higher, more abstract layers.

### Key Takeaways
- [ ] Codebook models provide a structured way to analyze and interpret internal representations in sequence prediction tasks.
- [ ] The TOC-FSM dataset offers a controlled environment for studying model interpretability due to its algorithmic nature.
- [ ] Tokenization of states (e.g., 18 -> 1, 8) is a fundamental aspect of preparing sequential data for these models.
- [ ] Code purity is a crucial metric, indicating how uniquely a code represents an input, with high purity in early layers suggesting effective resolution of superposition.
- [ ] Superposition, where multiple inputs map to the same hidden representation, can be mitigated by codebook training in initial layers.
- [ ] Jensen-Shannon Divergence (JSD) is a powerful tool for quantifying the impact of internal model changes on output probability distributions.
- [ ] Intervening on specific model components (e.g., attention heads, MLP layers) through "patching" allows for targeted analysis of their influence.
- [ ] States grouped by the same learned codes tend to have more similar output distributions, validating the model's ability to cluster semantically related inputs.
- [ ] The influence of learned codes on output distributions can be visualized to understand which parts of the model play significant roles in decision-making.

### Conclusion
This tutorial has demonstrated a comprehensive approach to interpreting codebook models applied to algorithmic sequence data. By meticulously setting up the model, analyzing code purity, intervening on internal state codes, and examining how inputs are grouped, we gain profound insights into the model's learning process. The findings confirm that codebook training can effectively resolve the superposition problem in early layers, leading to clear and interpretable representations.

Furthermore, the ability to measure the impact of code interventions using JS divergence highlights how specific internal codes and model components (like attention or MLP layers) significantly influence the final output distribution. This understanding is not merely academic; it suggests that by understanding and potentially manipulating these learned codes, we could "steer" the model towards desired outputs or behaviors. Such interpretability is vital for building trustworthy and controllable AI systems, moving us closer to a future where complex models are not just powerful, but also transparent and explainable.
