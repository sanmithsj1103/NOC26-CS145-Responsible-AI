# Interpretability Hands-on - Part 1

### Introduction

In the rapidly evolving landscape of artificial intelligence, neural networks have achieved remarkable feats across various domains. However, their inherent complexity often renders them opaque, making it challenging to understand *why* they make certain decisions or generate specific outputs. This lack of interpretability can be a significant barrier, particularly in sensitive applications where trust and accountability are paramount. This tutorial delves into a powerful technique designed to demystify these complex models: codebook features.

Codebook features offer a novel approach to enhance the interpretability and controllability of neural networks. By introducing discrete, learnable codebook entries directly into the model's layers, they create a structured bottleneck that transforms continuous activations into more understandable, discrete representations. This process not only provides a window into the internal workings of the network but also offers a mechanism to actively steer its behavior, allowing us to guide its generation towards specific topics or patterns. Understanding and applying codebook features is crucial for anyone looking to build more transparent, controllable, and ultimately, more trustworthy AI systems.

### Core Concepts

| Term | Definition | Significance |
| :--- | :--- | :--- |
| **`Codebook Features`** | A method that incorporates discrete, learnable entries into neural network layers, converting continuous activations into discrete codes. | Enhances interpretability and controllability by providing a structured, discrete representation of internal states. |
| **`Vector Quantization`** | The process by which continuous activations within a neural network layer are converted into discrete codes by finding the closest matching vector in a predefined set (the codebook). | Creates a bottleneck that simplifies complex continuous data into manageable, discrete units, aiding in pattern recognition and steering. |
| **`Codebook Entries`** | A set of fixed vectors learned by the network, representing discrete codes that the model uses instead of raw continuous activations. | These are the fundamental building blocks for discrete representation, allowing the model to focus on specific patterns or features. |
| **`Loss Function (Codebook)`** | An extended loss function that includes an L2 norm between the input to the codebook and its output, alongside the neural network's existing loss. | Minimizes the difference between continuous input and discrete output, ensuring the codebook accurately represents the data while enabling discrete control. |
| **`Stop Gradient (SG)`** | A notation used in the loss function indicating that during backpropagation, gradients will not flow through a specific part of the computation graph. | Prevents the gradient from flowing back through the codebook output, ensuring that the codebook entries are learned effectively without disrupting the main network training. |
| **`Steering`** | The ability to guide a neural network's output or generation towards a specific topic, theme, or pattern by activating particular codebook entries. | Allows for fine-grained control over model behavior, enabling targeted content generation or modification based on desired attributes. |
| **`Hooked Model`** | A modified version of the original neural network model, often created by wrapping it with additional functionality (like codebook features) for inspection or intervention. | Facilitates the integration and testing of interpretability techniques without altering the core architecture of the original model. |
| **`Topic Codes`** | Specific numerical identifiers or vectors within the codebook that correspond to distinct topics or concepts (e.g., "dragon," "baby," "video game"). | These are the direct levers used for steering, allowing users to activate specific conceptual representations within the model. |

### Detailed Analysis

#### 1. Understanding Codebook Features and Their Mechanism

Codebook features are a powerful interpretability method that integrates discrete learnable entries directly into the layers of neural networks. This integration transforms the continuous activations within a layer into discrete codes, effectively creating a bottleneck. Imagine continuous activations as a spectrum of values (e.g., 0.1, 0.2), which are then mapped to specific discrete values (e.g., 18, 19). This process is known as vector quantization. The network learns a set of fixed vectors, referred to as codebook entries, and uses these discrete codes to represent data in each layer, rather than the raw continuous activations. This mechanism helps the network focus on specific patterns or features, making the model more understandable and controllable.

The core of this approach lies in its modified loss function. While the neural network retains its original loss function (L_ways), an additional component is introduced to manage the codebook's learning:
`L = L_ways + ||C_out - SG(C_in)||_2^2`
Here, `C_out` represents the output of the codebook at a given layer, and `C_in` is the input to the codebook at that same layer. The `SG` (Stop Gradient) notation is crucial; it ensures that during backpropagation, gradients do not flow through the `C_in` part. This means the codebook output `C_out` is encouraged to be as close as possible to the input `C_in` (measured by the L2 norm, or Euclidean distance), but the learning process for `C_in` itself is not directly influenced by this specific term. For instance, if the word "cat" is processed in layer 3, the network finds the closest matching vector in its codebook. The output of layer 3 then becomes this closest codebook vector, which ideally represents "cat" or a similar concept. The purpose of this loss component is to minimize the distance between the codebook's output and its input, ensuring the discrete representation accurately reflects the continuous input.

#### 2. Steering Model Generation with Codebook Features

One of the most compelling applications of codebook features is their ability to "steer" the model's generation towards specific topics. This is achieved by identifying and activating particular codebook entries associated with desired concepts. For example, a specific code (e.g., 18) might correspond to "video game," while another (e.g., 12) might represent "movie."

The lecture provides a clear illustration:
* **Original Generation**: Given the prompt "The war was fought," the model might generate a neutral historical account like "On two fronts, the war was initiated in 1940 in Lapland."
* **Steered Generation (Video Game)**: By providing the "video game" topic and its corresponding code (e.g., 18), the model, given the *same* prompt, generates text like "The war was fought on both sides and was only the second game to deal with one of the battle followers in SimCity 2D Blade 2..." This output clearly relates to video games.
* **Steered Generation (Football)**: Similarly, steering towards "football" with the same prompt yields text such as "In its first 40 years, in the summer of 1946, the Cardinals of All-American Football Conference were rapidly..." This demonstrates the model's capacity to generate content aligned with the specified topic.

This steering capability allows users to control the thematic direction of the model's output, making it a powerful tool for content generation and fine-tuning.

#### 5. Applying Codebook Steering

Once the models are set up and verified, the actual steering process can begin.
- **Identifying Topic Codes**: Authors often provide pre-identified codes for specific topics at particular layers and attention heads. For instance, "dragon" might correspond to code 4670 at layer 0, attention head 13. These codes are crucial for targeted steering.
- **Defining Codes for Steering**: A dictionary or similar structure is used to map topics (e.g., "dragon," "baby," "flower") to their respective codebook entries.
```python
# Example: Defining topic codes
codes = {
"dragon": [(0, 13, 4670), (0, 13, 17640)],
"baby": [(0, 13, 1234), (0, 13, 5678)],
# ... other topics
}
```
- **Converting to `CodeInfo`**: The raw code definitions are converted into a `CodeInfo` object, which is the format expected by the `codebook_features` library.
- **Generating Steered Text**: A starting prompt (e.g., "Once upon a time") is provided, and the `generate_with_codes` function is invoked. This function takes the model, the input text, and the `CodeInfo` object for the desired topic (e.g., "baby") to generate text steered towards that topic.

#### 6. Quantitative Evaluation of Steering

While qualitative observation shows that steering works, a quantitative evaluation is essential to confirm its effectiveness and robustness.
- **Generating Multiple Prompts and Topics**: To assess steering comprehensively, prompts are generated using various starting sentences (e.g., "Once upon a time," "Once there was," "A long time ago") across all defined topics and their corresponding codes. This creates a `prompt_completions_set` containing all generated outputs.
- **Calculating Steering Metrics**: Two key metrics are calculated:
* **`topic_in_prompt_completion`**: This measures how often the target topic (e.g., "baby") appears in the 10 generated stories for a *specific* steered prompt. It's akin to a "term frequency" for the target topic within its intended generation.
* **`topic_in_prompt_completion_average`**: This metric assesses how often the target topic appears *across all generations*, including those steered towards *other* topics. This helps determine if the steering is specific to the intended topic or if the topic appears generally. It's similar to an "inverse document frequency" concept, ensuring the steering is unique and not just a common occurrence.
- **Baseline Comparison**: The same process of generating prompts and calculating metrics is performed for the *original model* (without any steering). This provides a baseline to compare against the steered generations.
- **Analyzing Results**: The results clearly demonstrate the impact of steering. For instance, in the baseline, "dragon" might appear 0% of the time. However, when steered towards "dragon," its occurrence jumps significantly (e.g., 77.5%). Similarly, "baby" might appear only 2.5% in the baseline but 97.5% when explicitly steered. This quantitative evidence confirms that codebook features effectively guide the model's output towards desired topics, making the model's behavior both interpretable and controllable.
