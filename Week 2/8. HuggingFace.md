# Hugging face

### Introduction

In the rapidly evolving landscape of artificial intelligence, Large Language Models (LLMs) like BERT and GPT have revolutionized how we approach natural language processing tasks. However, the sheer complexity of these models, from their intricate architectures to the vast computational resources required for training, historically made their implementation and deployment a daunting task. Before the advent of specialized libraries, even integrating a pre-trained model like BERT into an existing codebase could demand hundreds of lines of custom code, managing everything from tokenization to weight loading.

This lecture introduces Hugging Face, a pivotal library that has profoundly democratized the use and development of LLMs. By abstracting away much of this complexity, Hugging Face enables researchers and developers to leverage state-of-the-art models with remarkable ease and efficiency. It serves as a central hub where new models are frequently hosted, often concurrently with their research paper publications, ensuring immediate accessibility. This session aims to provide a foundational understanding of Hugging Face's core functionalities, offering a gateway into its extensive ecosystem and empowering users to explore its vast capabilities for various AI tasks.

### Core Concepts

| Term | Definition | Significance |
| :--- | :--- | :--- |
| **`Tokenizer`** | A component that converts raw text into numerical tokens, which are the input format for language models. | Essential first step for any NLP task, breaking down human language into a machine-understandable format. |
| **`Subword Tokenization`** | A tokenization strategy that breaks words into smaller units (subwords) to balance vocabulary size and sequence length. | Optimizes efficiency by handling rare words and reducing out-of-vocabulary issues, common in modern LLMs. |
| **`Special Tokens`** | Unique tokens added to input sequences for specific purposes, such as marking the start/end of a sequence or padding. | Provide crucial contextual information to models, enabling tasks like sequence classification and handling variable input lengths. |
| **`AutoTokenizer`** | A Hugging Face class that automatically selects and loads the correct tokenizer for a given pre-trained model. | Simplifies tokenization by removing the need to manually identify and import model-specific tokenizer classes. |
| **`Pipeline`** | A high-level abstraction in Hugging Face for performing common NLP tasks (e.g., sentiment analysis) with minimal code. | Offers a streamlined way to perform inference on pre-trained models without needing to manage tokenization or model loading explicitly. |
| **`AutoModel`** | A Hugging Face class that automatically loads the appropriate model architecture and pre-trained weights for a given task. | Facilitates easy access to a wide range of pre-trained models, abstracting away model-specific loading complexities. |
| **`AutoModelForSequenceClassification`** | A specialized `AutoModel` class designed for sequence-level classification tasks, such as sentiment analysis. | Provides a ready-to-use model head for classification, directly outputting logits for specific classes. |
| **`Trainer API`** | A high-level API in Hugging Face that abstracts away the complexities of the training loop for fine-tuning models. | Simplifies model training by handling data loaders, optimizers, learning rate schedulers, and evaluation metrics automatically. |
| **`Learning Rate Scheduler`** | An algorithm that adjusts the learning rate during training, often decreasing it over time or in cycles. | Optimizes the training process by allowing for larger steps early on and finer adjustments as the model converges, preventing overshooting. |
| **`Attention Mask`** | A binary mask used to indicate which parts of an input sequence the model should pay attention to, especially for padded sequences. | Prevents the model from attending to padding tokens, ensuring that computations are focused on meaningful input. |

### Detailed Analysis

#### 1. Tokenization: The First Step in NLP

Tokenization is the fundamental process of converting raw text into a sequence of numerical tokens that a machine learning model can understand. The lecture highlights different levels of tokenization:
* **Character-level**: Small vocabulary, but very long sequence lengths.
* **Word-level**: Large vocabulary, but contained sequence lengths.
* **Subword-level**: A more efficient approach that balances vocabulary size and sequence length by breaking words into smaller, meaningful units. This is commonly used in modern LLMs.

Hugging Face significantly simplifies tokenization, especially given that different models often use distinct tokenization methods or are trained on different corpora. Instead of manually selecting a tokenizer, users can leverage the `AutoTokenizer` class.

```python
from transformers import AutoTokenizer

# Load a tokenizer for a specific model (e.g., 'bert-base-uncased')
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

# Tokenize a sentence
sentence = "Using a transformer network is simple."
tokenized_output = tokenizer(sentence)
print(tokenized_output)
```

The `AutoTokenizer` automatically identifies the correct tokenizer based on the model name and handles the entire process. It returns `input_ids` (numerical representations of tokens) and `attention_mask` (indicating which tokens are actual content versus padding).

**Special Tokens**: Models often use special tokens to convey additional information. For instance, BERT uses:
* `[CLS]` (101): A classification token typically placed at the beginning of a sequence, designed to capture a sequence-level embedding for tasks like sentiment analysis.
* `[SEP]` (102): A separator token used to mark the end of a sentence or to separate two distinct sentences in a pair.
* `[PAD]` (0): A padding token used to make all input sequences the same length, with the `attention_mask` indicating these should be ignored.

When a word is broken into subwords, BERT's byte pair tokenizer uses `##` to indicate that a token is a subword and not a complete word (e.g., `trans` and `##formers`).

#### 2. Inference with Hugging Face Pipelines

For tasks where you simply want to use a pre-trained model for inference without any training, Hugging Face's `pipeline` construct offers an incredibly efficient solution. It abstracts away all the underlying complexities of tokenization, model loading, and output processing.

```python
from transformers import pipeline

# Create a sentiment analysis pipeline
sentiment_analyzer = pipeline("sentiment-analysis")

# Analyze sentiment for sentences
results = sentiment_analyzer(["IIIT Hyderabad has a beautiful campus.", "It's too humid."])
print(results)
```

The `pipeline` automatically selects a default model for the specified task (e.g., sentiment analysis). Users can also explicitly specify a model to use:

```python
# Specify a particular model for the pipeline
sentiment_analyzer_specific = pipeline("sentiment-analysis", model="distilbert-base-uncased-finetuned-sst-2-english")
results_specific = sentiment_analyzer_specific(["IIIT Hyderabad has a beautiful campus.", "It's too humid."])
print(results_specific)
```

Internally, the `pipeline` performs several steps: it loads the appropriate tokenizer, tokenizes the input, loads the specified model, passes the tokenized input through the model, and then processes the output (e.g., applying softmax for classification) to provide a user-friendly result.

#### 3. Loading Models and Obtaining Raw Embeddings

Beyond pipelines, Hugging Face allows for more granular control over model loading and output. The `AutoModel` class is used to load a pre-trained model and obtain its raw embeddings.

```python
from transformers import AutoModel, AutoTokenizer
import torch

# Load tokenizer and model
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")

# Tokenize input
sentences = ["IIIT Hyderabad has a beautiful campus.", "It's too humid."]
inputs = tokenizer(sentences, padding=True, truncation=True, return_tensors="pt")

# Pass inputs to the model
with torch.no_grad():
outputs = model(**inputs)

# The last_hidden_state contains the raw embeddings
print(outputs.last_hidden_state.shape) # Example output: torch.Size([2, 12, 768])
```

In this example, `outputs.last_hidden_state` provides the contextualized embeddings for each token in the input sequence. The shape `[2, 12, 768]` indicates 2 sentences, a maximum sequence length of 12 tokens (after padding), and an embedding dimension of 768. The `attention_mask` plays a crucial role here, indicating which of the 12 tokens are actual content (1) and which are padding (0), ensuring the model only processes relevant information.

#### 4. Sequence Classification with Specialized Models

For specific tasks like sequence classification (e.g., sentiment analysis, spam detection), Hugging Face provides specialized model classes that include a classification head on top of the base model. `AutoModelForSequenceClassification` is one such class.

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer
import torch

# Load tokenizer and model for sequence classification
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModelForSequenceClassification.from_pretrained("bert-base-uncased", num_labels=2) # num_labels for positive/negative

# Tokenize input
sentences = ["IIIT Hyderabad has a beautiful campus.", "It's too humid."]
inputs = tokenizer(sentences, padding=True, truncation=True, return_tensors="pt")

# Pass inputs to the model
with torch.no_grad():
outputs = model(**inputs)

# The logits are the raw scores before softmax
logits = outputs.logits
print(logits.shape) # Example output: torch.Size([2, 2])

# Apply softmax to get probabilities
probabilities = torch.softmax(logits, dim=-1)
print(probabilities)
```

This model directly outputs `logits` (raw scores) for each class, which can then be converted into probabilities using a softmax function. This simplifies the process compared to using `AutoModel` and manually adding a classification layer.

#### 5. Training Custom Models

Hugging Face also supports fine-tuning pre-trained models on custom datasets. The general workflow involves:
1. **Loading Datasets**: Hugging Face provides access to many standard datasets (e.g., GLUE, MRPC) with a single line of code. Custom datasets can also be integrated.
```python
from datasets import load_dataset
dataset = load_dataset("glue", "mrpc")
```
2. **Tokenization**: Define a tokenization function that applies the chosen tokenizer to the dataset.
```python
def tokenize_function(examples):
return tokenizer(examples["sentence1"], examples["sentence2"], truncation=True)

tokenized_datasets = dataset.map(tokenize_function, batched=True)
```
3. **Data Loaders**: Create PyTorch `DataLoader` objects to efficiently feed data in batches to the training loop.
4. **Model Declaration**: Load the appropriate `AutoModelForSequenceClassification` with the correct number of labels.
5. **Optimizer and Learning Rate Scheduler**: Initialize an optimizer (e.g., AdamW) and a learning rate scheduler. Schedulers dynamically adjust the learning rate during training, often starting high for exploration and decreasing for fine-tuning.
6. **Training Loop**: Implement a standard PyTorch training loop, including forward pass, loss calculation, backward pass, and optimizer/scheduler updates.

#### 6. Streamlining Training with the Trainer API

For most standard fine-tuning scenarios, Hugging Face's `Trainer` API significantly simplifies the training process by abstracting away the boilerplate code of the training loop.

```python
from transformers import Trainer, TrainingArguments, AutoModelForSequenceClassification, AutoTokenizer
from datasets import load_dataset

# 1. Load dataset and tokenizer
dataset = load_dataset("glue", "mrpc")
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

def tokenize_function(examples):
return tokenizer(examples["sentence1"], examples["sentence2"], truncation=True)

tokenized_datasets = dataset.map(tokenize_function, batched=True)

# 2. Define training arguments
training_args = TrainingArguments(
output_dir="./results",
num_train_epochs=3,
per_device_train_batch_size=16,
per_device_eval_batch_size=16,
warmup_steps=500,
weight_decay=0.01,
logging_dir="./logs",
logging_steps=10,
)

# 3. Load model
model = AutoModelForSequenceClassification.from_pretrained("bert-base-uncased", num_labels=2)

# 4. Create Trainer instance
trainer = Trainer(
model=model,
args=training_args,
train_dataset=tokenized_datasets["train"],
eval_dataset=tokenized_datasets["validation"],
tokenizer=tokenizer,
)

# 5. Start training
trainer.train()
```

The `Trainer` API handles data loading, batching, optimizer initialization, learning rate scheduling, gradient accumulation, and evaluation. Users define `TrainingArguments` to configure parameters like epochs, batch size, and learning rate schedule. This dramatically reduces the amount of custom code required for training, allowing developers to focus on model architecture and data preparation. While custom training loops are still possible for highly specialized architectures or training regimes, the `Trainer` API covers a vast majority of use cases.
