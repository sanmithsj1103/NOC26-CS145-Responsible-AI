# PyTorch - Classification

### Introduction
In the realm of machine learning, classification stands as a fundamental task, enabling systems to categorize data into predefined classes. Unlike regression, which predicts continuous values, classification deals with discrete outcomes, such as identifying an image as a cat or a dog, or determining if an email is spam. This tutorial builds upon previous PyTorch concepts, transitioning from simple regression problems to the more intricate world of classification using neural networks.

Understanding classification is crucial for developing intelligent systems that can make decisions based on patterns in data. PyTorch, with its flexible and dynamic computational graph, provides an excellent framework for building, training, and evaluating classification models. This lesson will guide you through the practical steps of setting up a classification problem, from preparing non-linear data to designing and optimizing neural network architectures that can effectively distinguish between different categories.

### Core Concepts
| Term | Definition | Significance |
| :--- | :--- | :--- |
| **`make_circles`** | A scikit-learn utility to generate a synthetic 2D dataset with two classes forming concentric circles. | Provides a classic example of non-linearly separable data, highlighting the need for non-linear models. |
| **`torch.Tensor`** | PyTorch's fundamental data structure, a multi-dimensional array optimized for numerical operations on GPUs. | Essential for all data processing in PyTorch; neural networks operate directly on tensors. |
| **`device agnostic`** | Code designed to run seamlessly on different hardware, typically CPUs or GPUs, based on availability. | Ensures code portability and leverages GPU acceleration when available for faster training. |
| **`nn.Module`** | The base class for all neural network modules in PyTorch, allowing for custom layer definitions and forward passes. | Provides a structured way to define complex network architectures beyond simple sequential layers. |
| **`nn.Sequential`** | A container module that passes data through a series of layers in a sequential order. | Useful for defining simple, feed-forward networks where data flow is strictly linear. |
| **`BCELossWithLogits`** | Binary Cross-Entropy Loss with Logits, a loss function for binary classification that combines sigmoid and BCE loss. | Numerically stable and efficient for binary classification, directly taking raw model outputs (logits). |
| **`ReLU`** | Rectified Linear Unit, a non-linear activation function that outputs the input directly if positive, otherwise zero. | Introduces non-linearity into neural networks, enabling them to learn complex, non-linear decision boundaries. |
| **`make_blobs`** | A scikit-learn utility to generate isotropic Gaussian blobs for clustering or classification. | Creates synthetic multi-class data, useful for demonstrating multi-class classification problems. |
| **`CrossEntropyLoss`** | A loss function commonly used for multi-class classification problems. | Suitable for scenarios with more than two classes, combining `LogSoftmax` and `NLLLoss` for numerical stability. |

### Detailed Analysis
#### 1. Data Preparation for Classification
The journey into classification begins with data. For this tutorial, we start by generating synthetic data that presents a clear challenge for linear models. The `make_circles` function from scikit-learn is employed to create a dataset where two classes are arranged in concentric circles, making them non-linearly separable. This dataset consists of two input features (`x1`, `x2`) and a binary label (`0` or `1`).

```python
# Example of generating dummy data (conceptual, actual code uses make_circles)
from sklearn.datasets import make_circles
X, y = make_circles(n_samples=1000, noise=0.03, random_state=42)
# X contains two-dimensional inputs, y contains binary labels
```

Once the data is generated, it must be converted into `torch.Tensor` objects, which are PyTorch's native data structure for computations. This involves using `torch.from_numpy()` and specifying the desired data type, typically `float32` for inputs and `long` for labels in classification.

```python
import torch
import numpy as np
# Assuming X_numpy and y_numpy are numpy arrays
X_tensor = torch.from_numpy(X_numpy).type(torch.float32)
y_tensor = torch.from_numpy(y_numpy).type(torch.long) # or float32 for BCELossWithLogits
```

Finally, the dataset is split into training and testing sets to evaluate the model's generalization ability. A common split ratio, such as 80% for training and 20% for testing, is applied.

#### 2. Building a Device-Agnostic Neural Network (Model V0)
Before defining the network architecture, it's crucial to set up the computing `device` to ensure the code can run efficiently on either a CPU or a GPU. This makes the code "device agnostic."

```python
device = "cuda" if torch.cuda.is_available() else "cpu"
print(f"Using device: {device}")
```

The initial model (Model V0) is a simple feed-forward neural network. PyTorch offers two primary ways to define network architectures: inheriting from `nn.Module` for custom, complex designs, or using `nn.Sequential` for straightforward, layer-by-layer constructions.

For Model V0, we define a class inheriting from `nn.Module`. This model consists of two linear layers. The input size is 2 (for `x1`, `x2`), which is expanded to 5 features in the first layer, and then reduced to 1 output feature in the second layer.

```python
from torch import nn
class CircleModelV0(nn.Module):
def __init__(self):
super().__init__()
self.layer_1 = nn.Linear(in_features=2, out_features=5)
self.layer_2 = nn.Linear(in_features=5, out_features=1)

def forward(self, x):
return self.layer_2(self.layer_1(x))

model_0 = CircleModelV0().to(device)
```

An alternative, more concise way to define simple sequential models is using `nn.Sequential`. This approach assumes a strictly sequential flow of data through the layers.

```python
model_0_sequential = nn.Sequential(
nn.Linear(in_features=2, out_features=5),
nn.Linear(in_features=5, out_features=1)
).to(device)
```
While `nn.Sequential` is convenient for simple architectures, `nn.Module` provides greater flexibility for prototyping complex networks where data flow might not be strictly sequential (e.g., skip connections, multiple inputs/outputs).

#### 3. Loss Functions and Converting Logits to Predictions
For binary classification, the `BCELossWithLogits` is a suitable loss function. It is numerically stable as it combines the sigmoid activation and binary cross-entropy loss into a single function, operating directly on the raw outputs (logits) of the model.

```python
loss_fn = nn.BCEWithLogitsLoss()
```

The model's raw output, known as "logits," can be any real number. To convert these logits into class predictions (0 or 1), a two-step process is typically used:
1. **Sigmoid Activation**: Apply a sigmoid function to the logits. This squashes the output to a range between 0 and 1, which can be interpreted as probabilities.
```python
y_pred_probs = torch.sigmoid(model_0(X_test.to(device)))
```
2. **Thresholding**: Apply a threshold (commonly 0.5) to these probabilities. If the probability is above the threshold, it's classified as class 1; otherwise, it's class 0. Rounding can achieve this for a 0.5 threshold.
```python
y_pred_labels = torch.round(y_pred_probs)
```
This process transforms the continuous model output into discrete class labels, which can then be compared with the true labels to calculate accuracy.

#### 4. The Training Loop and Initial Model Performance (Model V0)
The training process follows a standard PyTorch workflow:
1. **Epochs**: Define the number of training iterations.
2. **`model.train()`**: Set the model to training mode, enabling features like dropout and batch normalization.
3. **Forward Pass**: Feed input data through the model to get predictions (logits).
4. **Loss Calculation**: Compute the loss between predictions and true labels using the chosen loss function.
5. **`optimizer.zero_grad()`**: Clear previous gradients.
6. **Backward Pass (`loss.backward()`)**: Compute gradients of the loss with respect to model parameters.
7. **Optimizer Step (`optimizer.step()`)**: Update model parameters using the calculated gradients.
8. **`model.eval()`**: Set the model to evaluation mode, disabling training-specific layers.
9. **Evaluation**: Calculate metrics (e.g., accuracy, test loss) on the test set.

For Model V0, despite training, the accuracy plateaus around 50%, indicating it's performing no better than random guessing. Visualizing the decision boundary reveals a straight line, which is insufficient to separate the concentric circle data. This demonstrates that a simple linear model cannot learn the complex, non-linear patterns required for this dataset.

#### 5. Attempting Improvement with More Layers and Depth (Model V1)
To address the poor performance of Model V0, an attempt is made to increase the model's capacity by adding more linear layers and increasing the number of features in each layer. Model V1 introduces an additional linear layer and expands the `out_features` from 5 to 10 in the intermediate layers.

```python
class CircleModelV1(nn.Module):
def __init__(self):
super().__init__()
self.layer_1 = nn.Linear(in_features=2, out_features=10)
self.layer_2 = nn.Linear(in_features=10, out_features=10)
self.layer_3 = nn.Linear(in_features=10, out_features=1)

def forward(self, x):
return self.layer_3(self.layer_2(self.layer_1(x)))

model_1 = CircleModelV1().to(device)
```
Despite these architectural changes, Model V1 still yields similar poor results. The decision boundary remains linear, and accuracy hovers around 50%. This highlights a critical limitation: simply adding more linear layers does not enable a neural network to learn non-linear relationships. The composition of multiple linear transformations is still a linear transformation.

#### 6. The Power of Non-Linearity: Introducing ReLU (Model V2)
The key missing piece for classifying non-linear data is the introduction of non-linear activation functions. These functions allow the network to learn complex, curved decision boundaries. The Rectified Linear Unit (`ReLU`) is a popular choice due to its computational efficiency.

Model V2 incorporates `ReLU` activation functions between the linear layers. The `forward` pass now applies `ReLU` after each linear transformation before passing the output to the next layer.

```python
class CircleModelV2(nn.Module):
def __init__(self):
super().__init__()
self.layer_1 = nn.Linear(in_features=2, out_features=10)
self.layer_2 = nn.Linear(in_features=10, out_features=10)
self.layer_3 = nn.Linear(in_features=10, out_features=1)
self.relu = nn.ReLU() # Non-linear activation function

def forward(self, x):
# Apply linear layer, then ReLU, then next linear layer, then ReLU...
return self.layer_3(self.relu(self.layer_2(self.relu(self.layer_1(x)))))

model_2 = CircleModelV2().to(device)
```
With the addition of `ReLU`, Model V2 dramatically improves performance. Both training and test accuracies increase significantly, and the decision boundary visualization now shows a non-linear curve that effectively separates the concentric circles. This demonstrates the fundamental role of non-linearities in enabling neural networks to model complex data distributions.

#### 7. Extending to Multi-Class Classification
The principles learned from binary classification extend to multi-class problems. For multi-class classification, we use `make_blobs` to generate data with more than two classes (e.g., four distinct clusters).

The main changes for multi-class classification are:
* **Output Layer**: The `out_features` of the final linear layer must match the number of classes. For four classes, the output layer will have `out_features=4`.
* **Loss Function**: `nn.CrossEntropyLoss()` is typically used. This loss function combines `LogSoftmax` and `NLLLoss` and works directly with raw logits, similar to `BCELossWithLogits`.

Interestingly, for the `make_blobs` dataset, even a model with only linear layers (without explicit non-linearities) can achieve high accuracy. This is because the `make_blobs` data, while having multiple classes, might be separable by linear decision boundaries or combinations thereof. This illustrates that the necessity of non-linearity depends on the inherent separability of the data itself. If data can be separated linearly, non-linearity is not strictly required.

#### 8. Model Evaluation Metrics
Beyond loss and accuracy, various metrics provide a more comprehensive understanding of a classification model's performance:
* **Accuracy**: The proportion of correctly classified instances.
* **Precision**: The proportion of positive identifications that were actually correct.
* **Recall (Sensitivity)**: The proportion of actual positives that were identified correctly.
* **F1-Score**: The harmonic mean of precision and recall, useful for imbalanced datasets.
* **Confusion Matrix**: A table showing the counts of true positives, true negatives, false positives, and false negatives.
* **Classification Report**: A summary of precision, recall, and F1-score for each class.

These metrics are crucial for a thorough evaluation, especially in scenarios where class imbalance might make accuracy alone misleading.

### Key Takeaways
- [ ] Classification problems involve predicting discrete categories, distinct from regression's continuous predictions.
- [ ] Data must be converted to `torch.Tensor` objects and split into training/testing sets.
- [ ] PyTorch code should be device-agnostic to leverage GPU acceleration when available.
- [ ] `nn.Module` allows for flexible, custom network architectures, while `nn.Sequential` is for simple, linear layer stacks.
- [ ] For binary classification, `nn.BCEWithLogitsLoss` is a robust choice, and model logits are converted to probabilities via `torch.sigmoid` and then to class labels via thresholding (e.g., `torch.round`).
- [ ] Linear models alone cannot learn non-linear decision boundaries, regardless of the number of layers or depth.
- [ ] Non-linear activation functions like `nn.ReLU` are essential for neural networks to learn complex, non-linear patterns in data.
- [ ] Multi-class classification requires adjusting the output layer's `out_features` to match the number of classes and typically uses `nn.CrossEntropyLoss`.
- [ ] The need for non-linearity depends on the inherent separability of the data; some multi-class problems can be solved with linear boundaries.
- [ ] Beyond accuracy, metrics like precision, recall, F1-score, and confusion matrices provide a more complete evaluation of classification models.
